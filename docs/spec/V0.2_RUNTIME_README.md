# Navigate the Pathway

A mobile-first, warm, mature prototype for premed students and the advisors who support them.

## What is implemented in the v0.2 prototype

- Versioned browser-persistent fictional state under `navigate-demo:v3`, including v2 migration, recovery messaging, and one-click reset
- Structured autosaved drafts for every primary student workflow
- Student navigation: What’s Next, Explore, Record, Community, and My Work
- Fictional-example start screen, four-card orientation, and guided administrator tour
- Nullable, skippable intake answers with eight inspectable starting routes and reviewer persona presets
- Rosie the Roadrunner guide using the supplied character render
- Complete create, review, and update workflows for all eight pathway destinations
- Fast experience capture with optional details, three reflection depths, study-strategy experiments, support mapping, story development, course planning, community participation, and advising preparation
- Private-first student scenario with situation-matched fictional autofill
- Private evolving saved work, action-based activity history, and student-controlled advising share
- A student-owned application export for completed experiences, reflections, and story fragments, with print/PDF and local text-download options that never touch advising visibility
- Asynchronous advisor inbox and Prepare → Understand → Ask → Plan → Reflect pathway
- Advisor practice reflections with selective supervisor sharing
- Explicitly seeded advisor and admin examples, separate from the normal student scenario
- Shared student/advisor state with advisor selection, exact preview, expiration, revocation, comments, and safe change history
- Moderated community interactions with observe, react, reply, post, report, and mute controls
- Returning-user orientation after 30 minutes and an administrator preset that simulates returning after three weeks
- Pilot administration, relationship, moderation, content-source, and reviewer-scenario views
- Visible confidentiality guardrails and client-side warnings for obvious identifying patterns
- Responsive layouts, focus-managed dialogs, status announcements, reduced-motion support, and fictional-data labeling

The prototype stores fictional demonstration progress only in the current browser. It deliberately does not collect real student records or connect to authentication, Supabase, email, or production analytics. `supabase/schema.sql` remains a dormant production-shaped foundation to activate only after the institution confirms privacy, evaluation, and possible IRB requirements.

## Suggested second-pair-of-eyes review

Review the prototype as a fictional, local demonstration rather than a production system. Useful questions include:

- Can a new student understand the purpose, privacy boundary, and next action without explanation from the research team?
- Do skipped intake questions remain genuinely neutral in both scoring and recommendation language?
- Can unfinished work be recovered without creating duplicate records?
- Does the normal student scenario remain private until the student chooses an advisor, previews the exact entries, and confirms sharing?
- Can an advisor see only the selected entries, and does revocation remove access immediately?
- Can every saved entry be reopened from My Work in two actions or fewer?
- Does Download for applications read as a personal copy, remain separate from Advising, omit unfinished drafts, and flag incomplete experience details without blocking export?
- Does the experience capture feel achievable in 30 seconds before optional details are opened?
- Are the student-facing labels plain enough for someone unfamiliar with advising or learning-science terminology?
- Do the Student and Advisor pathways remain visually and conceptually distinct on desktop and phone layouts?

## Run locally

```bash
npm install
npm run dev
```

Use the always-visible Student Pathway and Advisor Pathway controls to switch views. Open Pilot Administration from the advisor workspace. All records are fictional and local to the browser.
